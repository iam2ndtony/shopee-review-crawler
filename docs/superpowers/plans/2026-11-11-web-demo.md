# Web Demo: Shopee Product Review Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web page where the user pastes a Shopee product link (or opens a saved product) and gets an EDA of the reviews with the model's predicted sentiment, with every review openable.

**Architecture:** A new `vi_web/` package does URL checks, the crawl on a worker thread, the analysis and an in-memory job store, and mounts its routes plus a static page on the existing FastAPI app. Prediction code is extracted from `vi_clean/api.py` into `vi_clean/predictor.py` so `/predict` and the analysis share it. Saved products use the held-out predictions already in `shopee_oof.csv`.

**Tech Stack:** Python 3.13, FastAPI, pandas, Playwright (already in `requirements.txt`), plain HTML/CSS/JS with hand-drawn SVG charts.

**Spec:** `docs/superpowers/specs/2026-11-11-web-demo-design.md`

## Review Focus

1. Reviewer username, user id and avatar never reach the API output or the page (Tasks 2, 4, 5).
2. Review text containing HTML or script renders as plain text (Task 6).
3. Saved-mode counts reconcile (found = with text + stars-only; with text = predicted + not predicted) and a review with no held-out match is "not predicted", never a borrowed label (Task 3).
4. Look-alike URLs are rejected: `https://shopee.vn.evil.com/..`, `https://shopee.vn@evil.com/..`, `http://` links, missing ids (Task 4).
5. A second live job while one is active gives 409, a job never marked ready times out, a result before completion gives 409, an unknown job gives 404 (Tasks 4 and 5).

**Files:**

**Interfaces:**
- Produces in `config.py`: frozen dataclass `WebConfig` with `saved_dir: Path` (env `SAVED_REVIEWS_DIR`, default `ROOT/"raw_reviews"`), `profile_dir: Path` (env `SHOPEE_PROFILE_DIR`, default `ROOT/"shopee_chrome_profile"`), `default_max: int = 1000`, `max_cap: int = 3000`, `ready_timeout_s: float = 600`, `max_jobs: int = 5`, `page_limit: int = 50`, `delay_s: float = 1.0`, `retries: int = 3`; constant `MAX_CAP = 3000`.
- Produces in `analyze.py`:
  - `reviews_frame(items: list[dict]) -> pd.DataFrame`: columns `n` (1-based position), `stars` (int), `date` (UTC `YYYY-MM-DD` from `ctime`, `""` if missing), `variation` (`product_items[0].model_name` or `""`), `text` (stripped `comment`, `""` if null). Reads only `comment`, `rating_star`, `ctime`, `product_items`.
  - `product_id_of(items: list[dict]) -> str`: `s<shopid>_i<itemid>` from the first item, `""` if missing.
  - `flag_frame(df: pd.DataFrame) -> pd.DataFrame`: adds `cleaned` (`clean_texts`, `lowercase=False`, `""` for stars-only), `duplicate` (an earlier row has the same `md5_key(cleaned)`), `repetitive` (`low_ttr_mask` on `cleaned`); stars-only rows get both flags False.
  - `build_analysis(df: pd.DataFrame, mode: str, training_data_warning: bool) -> dict`: `df` also carries `label` (str or None) and `probs` (dict or None). Returns keys `summary` (`reviews_found`, `with_text`, `stars_only`, `predicted`, `not_predicted`, `share` per label over predicted, `duplicates`, `repetitive`, `disagreements`, `date_range` as `[first, last]` or null, `mode`, `training_data_warning`), `stars_all` (keys `"1"`..`"5"`), `sentiment_counts` (negative, neutral, positive), `stars_by_label` (stars key to the three counts), `by_month` (sorted list of `{month, negative, neutral, positive}` over predicted reviews with a date), `reviews` (text reviews only: `n, stars, date, variation, text, cleaned, label, probs, duplicate, repetitive, disagrees`). `disagrees` is 4 or 5 stars with Negative, or 1 or 2 stars with Positive; 3 stars never. An empty item list, or one with only stars-only reviews, returns a valid result with zero counts, `date_range` null and empty `by_month` and `reviews` (never an error).
